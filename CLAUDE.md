# Hexfinity

Blender 5.1+ extension that generates a grid of interlocking hexagonal terrain tiles with per-corner height control.

## Ignore the ideas.md file. Only containing notes

## Run / build

- **Tests** (uses Blender's bundled Python; seven modules below — `mesh_builder.py`, `map.py`, `manifold_check.py`, `procedural_surfaces.py`, `subdivision.py`, `tile_export.py`, `tree_pads.py` — are bpy-free so they import in plain CPython). Blender's bundled interpreter doesn't ship pytest, so install it once first:
  ```

  "C:\Program Files\Blender Foundation\Blender 5.1\5.1\python\bin\python.exe" -m pytest tests -v
  ```

- **Build / deploy**: `deploy.ps1` — zips to `dist/`, optionally junctions source into Blender's user extensions for live dev.
- **Extension manifest**: `blender_manifest.toml` (Blender 5.x format — not the legacy `bl_info` dict).

## Module map (`hexfinity/`)

| File | Responsibility |
|---|---|
| `__init__.py` | `register()` / `unregister()`; defers all bpy imports into `register()` |
| `properties.py` | `HexFinityMapProperties` (scene-level) + `HexFinityProperties` (per-tile P1–P6 corner heights), plus `HexFinityBrushProperties` (brush radius/strength/direction/preserve_edge), `HexFinityFloraProperties` (`flatten_base`/`pad_blend_mm`/`penetration_mm` — all three wired to `_on_flora_pad_update`, a lazy-import rebuild of every tile with a planted tree via `operators._rebuild_flora_tiles`), `HexFinitySurfacePoint`/`HexFinitySurfaceRegion` (procedural-surface region authoring), and `HexFinityTerrainProperties` (`snap_mm`/`snap_damp_mm`/`snap_tile` driving `apply_terrain_snap`) |
| `mesh_builder.py` | **bpy-free** — `build_hex_tile()`; top surface is Loop subdivision (via `subdivision.py`) over a 13-vertex control mesh (`C`, `P1..P6`, `Q1..Q6`) with sharp-tagged rim edges — supersedes the earlier Coons-patch construction; side walls; interlock tabs/holes. Optional `flora_pads` kwarg (list of `{"x","y","radius_mm","blend_mm"}`) locally refines+flattens the top surface under each planted tree's footprint via `tree_pads.refine_and_flatten`, called between the brush/procedural-surface displacement loop and top-face emission; collects `protected_edges` (the rim chains) so refinement can never split a rim edge. Optional `flora_notches`/`flora_notch_warnings`/`flora_notch_ok_indices`/`flora_notch_heights` kwargs, applied strictly after `flora_pads`, drill a blind cylindrical pin socket via `tree_pads.cut_notches`; `flora_notch_heights` receives `{index: pad_z}`, the exact pre-drill flat height per successful cut, so `flora.py` can seat a tree/pin there directly instead of raycasting into the hole it just cut. `FLORA_PIN_*`/`FLORA_NOTCH_*` constants (pin diameter 2mm, notch depth 10mm, tolerance 0.2mm — all hardcoded, independent of `man_height_mm`) live alongside `TAB_*` and are imported by `flora.py` as the single source of truth for both the tile-side socket and the tree-side pin object |
| `tree_pads.py` | **bpy-free** — `sample_surface_z()` (barycentric height lookup), `_iteratively_refine()` (the marked-edge adaptive subdivision loop shared by `refine_and_flatten` and `cut_notches`), and `refine_and_flatten()`: per-edge adaptive triangle refinement (crack-free by construction, capped at `MAX_LEVELS`) plus a per-vertex lerp-toward-pad-height flatten with a rim-edge-distance fade (mirrors the skirt fade in `operators._compute_snap_gap`). New vertices are always appended after the caller's existing vertex range, never inserted, so brush/snap displacement-layer indices stay valid. `cut_notches()` drills a blind cylindrical socket per notch spec: forces its own deeper refinement (`NOTCH_MAX_LEVELS`) than a pad's own flatten produces, removes triangles fully inside the notch radius, walks the hole's boundary into a loop via `_boundary_loop()` (rejecting pinch points/multiple loops via a boundary-edge-degree check), snaps the loop onto an exact circle, and builds the wall+floor by reusing the removed region's own triangulation (remapped down) rather than a fresh fan — so no interior vertex is ever orphaned. Skips a notch (appending a reason to `warnings`, recording successes in `ok_indices` and their pre-drill flat height in `resolved_heights` as `{index: pad_z}`) rather than risking a corrupt mesh when the local mesh is too coarse, the boundary is irregular, it reaches the rim, or the tile is too thin (`FLORA_NOTCH_MIN_FLOOR_MM`). Imported lazily from inside `mesh_builder.build_hex_tile` (only when `flora_pads`/`flora_notches` is non-empty) to avoid a circular import, since `tree_pads.py` itself imports from `mesh_builder` |
| `map.py` | **bpy-free** — odd-q offset math, `SHARED_CORNERS` table, `neighbour_coord()`, `find_tile()`, `tile_world_xy()`, `clamp_level()`/`apply_corner_delta()` |
| `manifold_check.py` | **bpy-free** — `assert_two_manifold(verts, faces)` validator run after every build |
| `subdivision.py` | **bpy-free** — `subdivide_loop()` (Loop subdivision with sharp-edge/crease support) and `linear_midpoint_subdivide()`; imported by `mesh_builder.py` for the top surface |
| `tile_export.py` | **bpy-free** — `tile_geometry_hash`, `short_hash`, `is_custom_tile`, `tile_filename`, `manifest_rows`: dedup/naming/manifest helpers consumed by `operators.HEXFINITY_OT_export_tiles` |
| `operators.py` | `generate_map`, `clear_map` (destructive-only — deletes the whole map collection + all tiles/terrain/scatter/flora, incl. the Flora sub-collection, resets `is_generated`/`show_globals`; does **not** rebuild), `on_global_update` callback; `_REBUILDING` re-entrancy guard. `rebuild_tile(obj, finalize_flora=False)` computes `flora.pad_specs(obj)` and passes it as `build_hex_tile`'s `flora_pads` kwarg *before* the build call, then (unchanged) calls `flora.purge_flora`/`flora.sync_flora` (mirroring the scatter block just above it) after the new mesh is assigned + depsgraph updated. `_compute_snap_gap`'s undisplaced baseline build passes `flora_pads=None` explicitly — it must stay a clean unpadded reference. `finalize_flora` (default `False`, unchanged at all 12 pre-existing call sites) additionally computes `flora.notch_specs(obj)` and passes `flora_notches`/collects `flora_notch_warnings`/`flora_notch_ok_indices`/`flora_notch_heights` (`{index: pad_z}`, the exact pre-drill flat height per successful cut — passed to `flora.sync_flora` as `notch_heights` so it seats a tree/pin from the known height instead of raycasting into the hole it just cut); `flora.sync_flora(obj, ok_indices=notch_ok_indices, notch_heights=notch_heights)` is the *only* flora call now (a pin is created as a child of its own tree object inside that same function, not via a separate pass) — `purge_flora` unconditionally clears every tree (and therefore its pin child) each rebuild, so pins/notches only exist right after a finalize pass. `_rebuild_flora_tiles()` rebuilds every tile with a flora placement (without finalizing), for the `flatten_base`/`pad_blend_mm`/`penetration_mm` property update callbacks (a pad setting is scene-wide, not per-tile) — which also means those callbacks silently strip any existing pins/notches, mitigated by the panel's manual `hexfinity.finalize_flora` button (`flora.HEXFINITY_OT_finalize_flora`). `_build_map` seeds every new tile's P1–P6/center at `map_props.base_level` before the first build (corner callbacks short-circuit while `is_generated` is still `False`). `on_corner_changed` also fans a corner edit's **delta** across a multi-selection: `_MULTI_APPLYING` guards the fan-out, and `_ACTIVE_SNAPSHOT`/`seed_corner_snapshot*` (seeded from `panel.py`) recover the pre-edit value Blender's update hook hides. Also: `HEXFINITY_OT_import_terrain_object`/`HEXFINITY_OT_redrop_terrain_object` (STL terrain-object placement/parenting), the terrain-snap-to-model subsystem (`apply_terrain_snap`, `_compute_snap_gap`, `_snap_signature`, `_reset_tile_snap`), and `HEXFINITY_OT_export_tiles` (per-tile STL export + dedup + manifest writing, via `tile_export.py`; `_terrain_children` excludes flora tree/pin objects from the fused tile export; each finalized tree exports as **two separate** STLs — `hex_qNN_rNN_treeII.stl` and `hex_qNN_rNN_treeII_pin.stl` via `_export_flora_pair`/`tile_export.flora_tree_filename`/`flora_pin_filename` — sharing the tile's own naming stem (not content-hash-deduped like tile files; every placement gets its own pair), listed in a separate `flora_manifest.csv`/`.json` (`tree_file`/`pin_file` columns); since the pin is parented to the tree with a fixed local transform, `_export_flora_pair` rotates/moves only the tree object (the pin is carried along rigidly) 180° about the tree's own local X axis before export — flipping the whole rigid tree+pin body upside down so the canopy tip (previously the assembly's highest point) becomes the new lowest point at world z=0, and the pin (previously lowest, hanging into the socket) becomes the new highest point, pointing up — confirmed with the user as the intended print orientation; warns — doesn't block — if a tile has planted trees with no matching pin, i.e. flora was never finalized) |

## Invariants — preserve when editing

- **bpy-free rule**: `mesh_builder.py`, `map.py`, `manifold_check.py`, `procedural_surfaces.py` (incl. all scatter geometry math), `subdivision.py`, `tile_export.py`, and `tree_pads.py` must never import `bpy`. That isolation is what lets the pytest suite run against Blender's bundled Python without launching Blender. `regions.py`/`scatter.py`/`flora.py` themselves do import `bpy` — keep object/raycast/boolean/STL-import code there, and keep any pure-math helpers extracted into it bpy-free.
- **Manifold guarantee**: every built tile is validated by `assert_two_manifold()`; failure raises loudly so silent mesh corruption is caught.
- **Tab geometry is hardcoded** in `mesh_builder.py` (`TAB_WIDTH_MM`, `TAB_HEIGHT_MM`, `TAB_DEPTH_MM`, `TAB_HOLE_TOLERANCE_MM`) — these constrain minimum base thickness and diameter. Check the constants before changing related values.
- **Corner sync**: `SHARED_CORNERS` in `map.py` defines which neighbours share each corner; `on_global_update` propagates per-corner writes across seams.
- **Scatter kind contract**: a `scatter` `Surface` has `generator=None`, so `surface_offset()` returns `0.0` (zero displacement) and the `GENERATING` test fan-out (`s.generator is not None`) excludes it — do not give a scatter surface a generator. Scatter objects are regenerated by `scatter.purge_scatter` + `sync_scatter` on every `rebuild_tile`; the seating raycast must run *after* the tile mesh is assigned and the depsgraph updated so it samples current (not stale) geometry.
- **Brush displacement layer**: top-surface verts are registered first in `build_hex_tile` (indices `0 .. num_top-1`), and `num_top` depends only on `smoothness_passes + resample_density` (see `top_vertex_count`, pinned to the builder by `test_top_vertex_count_matches_builder`). `obj["hf_brush_disp"]` is a `float[num_top]` z-offset layer applied (clamped to `base_thickness_mm`) inside the builder and re-sampled on every rebuild; `rebuild_tile` drops it when the length no longer matches `num_top` (a subdivision/resample change), which is the intended "paint survives height edits only" contract.
- **Tree-pad vertex ordering**: `tree_pads.refine_and_flatten` only ever *appends* new vertices — never inserts — so every index below the caller's original vertex count stays valid. `mesh_builder.build_hex_tile` calls it strictly between top-vertex displacement and the "Bottom of the tile…" section, so pad-refinement verts land at indices `>= num_top` and strictly before any bottom/side/tab vertex `add_vert` registers — planting/unplanting a tree therefore never disturbs `top_vertex_count()`, `hf_brush_disp`, or `hf_snap_disp`. Refinement must also never split a rim edge (`protected_edges`, collected from the same `rim_chains` the side wall's `top_rim_key` depends on) or the wall n-gon desyncs. `tree_pads.cut_notches` (run after `refine_and_flatten`, only when finalizing flora) keeps the same append-only contract for its wall/floor verts, but *does* mutate existing vertices in place: a socket's boundary-loop vertices get their (x, y) snapped onto an exact circle (z untouched), and any genuinely-interior vertex of the drilled region sinks straight to the socket floor (z changed, same index, reused for the floor mesh so nothing is ever orphaned) — both safe since brush/snap layers only ever read/write Z by index and both already ran earlier in the pipeline.

Plan lifecycle is driven by two trigger phrases in my prompts:

**Start:** `plan <name>.md: <prompt>`
→ Create `plans/brewing/<name>.md` containing the prompt and the proposed plan. Work proceeds against this file.

**End:** `end plan`
→ Move the active plan from `plans/brewing/` to `plans/implemented/` and append the Token Usage Report.

### Token Usage Report (appended on `end plan`)
Counts come from the API `usage` object on each response — never self-estimate.
Aggregate across all requests made since the matching `plan` trigger:

- Input tokens (prompt): sum of `usage.input_tokens`
- Cache tokens: `cache_creation_input_tokens` + `cache_read_input_tokens`
- Output tokens (answer): sum of `usage.output_tokens`
- MCP / tool-call tokens: input+output of requests issuing tool_use/tool_result
- Web request tokens: input+output of requests invoking web tools
- Source-search tokens: input+output of requests doing code/file search
- Project files read: count of distinct files opened
- Total tokens: input + output + cache
