# Hexfinity

Blender 5.1+ extension that generates a grid of interlocking hexagonal terrain tiles with per-corner height control.

## Ignore the ideas.md file. Only containing notes

## Run / build

- **Tests** (uses Blender's bundled Python; nine modules below — `mesh_builder.py`, `map.py`, `manifold_check.py`, `procedural_surfaces.py`, `subdivision.py`, `tile_export.py`, `tree_pads.py`, `terrain_pads.py`, `face_select.py` — are bpy-free so they import in plain CPython). Blender's bundled interpreter doesn't ship pytest, so install it once first:
  ```
  "C:\Program Files\Blender Foundation\Blender 5.1\5.1\python\bin\python.exe" -m pip install --user pytest
  "C:\Program Files\Blender Foundation\Blender 5.1\5.1\python\bin\python.exe" -m pytest tests -v
  ```
- **Build / deploy**: `deploy.ps1` — zips to `dist/`, optionally junctions source into Blender's user extensions for live dev.
- **Extension manifest**: `blender_manifest.toml` (Blender 5.x format — not the legacy `bl_info` dict).

| File | Responsibility |
|---|---|
| `__init__.py` | `register()` / `unregister()`; defers all bpy imports into `register()` |
| `properties.py` | `HexFinityMapProperties` (scene-level) + `HexFinityProperties` (per-tile P1–P6 corner heights, plus `is_baked` — a UI-only flag set/cleared by `operators.HEXFINITY_OT_bake_tile`/`HEXFINITY_OT_unbake_tile`; the actual frozen-geometry blobs live as raw id-properties on the Object, not RNA props — see `operators.py`'s row), plus `HexFinityBrushProperties` (brush radius/strength/direction/preserve_edge), `HexFinityFloraProperties` (`flatten_base`/`pad_blend_mm`/`penetration_mm` — all three wired to `_on_flora_pad_update`, a lazy-import rebuild of every tile with a planted tree via `operators._rebuild_flora_tiles`), `HexFinitySurfacePoint`/`HexFinitySurfaceRegion` (procedural-surface region authoring), `HexFinityTerrainProperties` (`snap_mm`/`snap_damp_mm`, both wired to `_on_terrain_snap_update` → `operators.on_terrain_snap_changed`, which just rebuilds the hex the model is parented to — `snap_mm` is purely a >0 gate read by `operators.terrain_pad_specs`/`_compute_terrain_pad_specs`, its exact value doesn't otherwise affect the result; And `HexFinityPathFeature` (per-tile: `name`/`feature_type` enum (`SIMPLE`/`GRAVEL`/`PAVED_ROAD`)/`width_mm`/`depth_mm`/`repeat_mm`/`texture` enum + `points` reusing `HexFinitySurfacePoint`. Every field has an `update=` that rebuilds the tile — Path Feature auto-carves on any edit, no manual gate. `texture` is set by `feature_type`'s autofill but is no longer drawn in the panel — `feature_type` alone determines it, `panel.py` never exposes its own dropdown for it. `feature_type`'s `update=_on_path_feature_type_update` is the sole autofill trigger: guarded by `_PATH_FEATURE_FILLING` (mirrors `_REGION_FILLING`), it calls `path_features.apply_type_defaults()` to set `width_mm` (a direct `man_height_mm` factor, model-scale-aware) plus fixed-literal `depth_mm`/`repeat_mm` (NOT scaled by man height) and pick a default `texture`, sets a `_default_path_feature_name()`-derived name if still empty, then rebuilds once — `path_features._commit_feature` relies on this single assignment firing correctly *even when the type equals the property's own Blender-level default*, since Blender's `update=` still fires on a same-value Python assignment) |
| `mesh_builder.py` | **bpy-free** — `build_hex_tile()`; top surface is Loop subdivision (via `subdivision.py`) over a 13-vertex control mesh (`C`, `P1..P6`, `Q1..Q6`) with sharp-tagged rim edges — supersedes the earlier Coons-patch construction; side walls; interlock tabs/holes. Optional `flora_pads`/`terrain_pads` kwargs (each a list of `{"x","y","radius_mm","blend_mm"}` dicts, `terrain_pads` entries also carrying an explicit `"z"`) are concatenated and locally refine+flatten the top surface via a single `tree_pads.refine_and_flatten` call, between the brush/procedural-surface displacement loop and top-face emission; collects `protected_edges` (the rim chains) so refinement can never split a rim edge. The two kwargs must be merged into one call, not two sequential ones — `refine_and_flatten` samples every pad's target *before* any flattening happens, so nearby flora/terrain pads sampling each other's post-flatten surface would double-blend where footprints overlap. Optional `flora_notches`/`flora_notch_warnings`/`flora_notch_ok_indices`/`flora_notch_heights` kwargs, applied strictly after the merged pad pass, drill a blind cylindrical pin socket via `tree_pads.cut_notches`; `flora_notch_heights` receives `{index: pad_z}`, the exact pre-drill flat height per successful cut, so `flora.py` can seat a tree/pin there directly instead of raycasting into the hole it just cut. `FLORA_PIN_*`/`FLORA_NOTCH_*` constants (pin diameter 2mm, notch depth 10mm, tolerance 0.2mm — all hardcoded, independent of `man_height_mm`) live alongside `TAB_*` and are imported by `flora.py` as the single source of truth for both the tile-side socket and the tree-side pin object. Optional `path_features` kwarg (a list of `{"points","width_mm","depth_mm","blend_mm","repeat_mm","pixels","tex_width","tex_height"}` dicts, one per drawn Path Feature line) is applied via a separate `tree_pads.refine_and_displace_along_path` call, strictly *after* the merged `flora_pads`/`terrain_pads` flatten pass and before `flora_notches` — a path carves into whatever the pad-flatten layer already produced, matching the topmost position in the user-facing Water/Land/Draw Area/Path Feature layer stack (see `tree_pads.py`'s row for the actual displacement math). Optional `baked_extra=(extra_verts, extra_faces, prefix_overrides)` (see `operators.HEXFINITY_OT_bake_tile`) short-circuits all four of the above — no `tree_pads` call at all — and instead, right after the top-vertex brush/region loop, applies `prefix_overrides` (`{top_vertex_index: z}`) to the freshly-generated top-vertex prefix and appends `extra_verts`/uses `extra_faces` verbatim, exactly where the live pad/notch/path pipeline would have left them; `top_displacement`/`surface_regions` are unaffected, since baking never touches them. Optional `bake_capture` (an output-only dict) is the inverse: given on a *live* build (i.e. `baked_extra=None`), it's filled in with `num_top`/`extra_verts`/`extra_faces`/`prefix_overrides` — everything `operators.rebuild_tile` needs to freeze that build's pad/notch/path result into a `baked_extra` tuple for a later call; `prefix_overrides` is computed by diffing each top-vertex's z immediately before vs. after the pad/notch/path section runs, since `tree_pads.refine_and_flatten`/`refine_and_displace_along_path` mutate pre-existing (not just newly-appended) vertices in place |
| `tree_pads.py` | **bpy-free** — `sample_surface_z()` (barycentric height lookup), `_iteratively_refine()` (the marked-edge adaptive subdivision loop shared by `refine_and_flatten` and `cut_notches`), and `refine_and_flatten()`: per-edge adaptive triangle refinement (crack-free by construction, capped at `MAX_LEVELS`) plus a per-vertex lerp-toward-pad-height flatten with a rim-edge-distance fade so a pad near the rim shrinks rather than desyncing the seam with the neighbouring tile. A pad dict may carry an explicit `"z"` target height instead of the default sampled-from-surface one — flora pads omit it, `operators.terrain_pad_specs` sets it to the terrain object's own target height, since a terrain plateau must move the surface to an externally-dictated height rather than just flatten wherever it already is (this is the *sole* mechanism that deforms a hex to match a terrain object — there is no separate raycast displacement layer). New vertices are always appended after the caller's existing vertex range, never inserted, so the brush displacement-layer indices stay valid. `cut_notches()` drills a blind cylindrical socket per notch spec: forces its own deeper refinement (`NOTCH_MAX_LEVELS`) than a pad's own flatten produces, removes triangles fully inside the notch radius, walks the hole's boundary into a loop via `_boundary_loop()` (rejecting pinch points/multiple loops via a boundary-edge-degree check), snaps the loop onto an exact circle, and builds the wall+floor by reusing the removed region's own triangulation (remapped down) rather than a fresh fan — so no interior vertex is ever orphaned. Skips a notch (appending a reason to `warnings`, recording successes in `ok_indices` and their pre-drill flat height in `resolved_heights` as `{index: pad_z}`) rather than risking a corrupt mesh when the local mesh is too coarse, the boundary is irregular, it reaches the rim, or the tile is too thin (`FLORA_NOTCH_MIN_FLOOR_MM`). Imported lazily from inside `mesh_builder.build_hex_tile` (only when `flora_pads`/`terrain_pads`/`flora_notches`/`path_features` is non-empty) to avoid a circular import, since `tree_pads.py` itself imports from `mesh_builder`. A third refine+apply strategy sharing `_iteratively_refine`, for Path Feature: `curvilinear_coords(x, y, points)` (nearest-segment projection of a point onto an open polyline → `(s, t)` = arc-length-along/signed-perpendicular-distance-from the centerline — clamped past the polyline's endpoints, not wrapped), `sample_grayscale(pixels, width, height, u, v)` (bilinear sample of a flat row-major grayscale array; `u` wraps, `v` clamps), and `refine_and_displace_along_path(verts, faces, protected_edges, paths, diameter_mm, base_thickness_mm)`: derives its own refinement pad-chain per path (small `{x,y,radius_mm,blend_mm}` circles stepped along the polyline, same shape `_iteratively_refine` already consumes) internally rather than requiring the caller to supply one, then for every vertex within `width_mm/2 + blend_mm` of a path samples `(s, t)` → texture `(u, v)` (`u = s / repeat_mm`, `v = 0.5 + t / width_mm`) and applies `offset = (gray - 0.5) * 2 * depth_mm` weighted by the same radial+rim-fade blend shape `refine_and_flatten` uses — **heightmap convention: white = +depth_mm (raised), mid-gray = unchanged, black = -depth_mm (carved)**. A path dict's `pixels` may be `None`, sampling as a constant `0.0` (solid black) — a uniform full-depth groove, not a no-op, so a line is visibly functional before any texture asset exists. Multiple overlapping paths apply sequentially, each adding its own weighted offset to whatever the previous one left (same shape as `refine_and_flatten`'s per-pad lerp loop) |
| `terrain_pads.py` | **bpy-free** — `cluster_grid_hits()`: tiles a boolean "under the model's flat base" grid (built by `operators._terrain_pad_grid_hits` via raycasting) into small circular pad specs by grouping cells into `block_cells x block_cells` blocks and fitting one circle per non-empty block from that block's own member cells. Deliberately block-tiling rather than one bounding circle per 4-connected region: a footprint that wraps around a hole (e.g. a ring) is still one connected region, but its centroid — and a single circle's full radius — can land squarely on the hole; block-tiling bounds any one pad's span to roughly `block_cells` grid cells, the same kind of grid-resolution limit the raycast sampling and notch-drilling code already live with elsewhere. Consumed by `operators.terrain_pad_specs`, which stamps each resulting pad with the terrain object's `snap_damp_mm` as `blend_mm` and its computed `target_z` as `"z"`, ready for `mesh_builder.build_hex_tile`'s `terrain_pads` kwarg |
| `map.py` | **bpy-free** — odd-q offset math, `SHARED_CORNERS` table, `neighbour_coord()`, `find_tile()`, `tile_world_xy()`, `clamp_level()`/`apply_corner_delta()`, `corner_xy(i, diameter_mm)` (the canonical P-corner XY formula — `mesh_builder.py`'s `corners_xy` and `overlay.py`'s `_tile_corner_world_positions` predate it and still duplicate the formula locally, left as-is) and `edge_snap_points(diameter_mm, edge_snap)` (the `6*(edge_snap-1)` unique tile-local rim points — each P corner plus `edge_snap-2` evenly-spaced interior points per edge — `path_features.py`'s snap-target list), `point_in_hex(x, y, diameter_mm)` (boundary-inclusive convex-polygon test over the six `corner_xy()` points — `path_features.py` uses it to reject a free waypoint click that falls outside the tile), and `hex_prism_verts_faces(diameter_mm, z_min, z_max)` (a closed, 2-manifold vertical hex prism — the tile-local hexagon extruded from `z_min` to `z_max` — used purely as a boolean-tool solid by `operators._cut_terrain_by_hex`, not for anything rendered) |
| `manifold_check.py` | **bpy-free** — `assert_two_manifold(verts, faces)` validator run after every build |
| `subdivision.py` | **bpy-free** — `subdivide_loop()` (Loop subdivision with sharp-edge/crease support) and `linear_midpoint_subdivide()`; imported by `mesh_builder.py` for the top surface |

| `face_select.py` | **bpy-free** — face-normal flood fill backing Draw Area's "Flood Fill" (magic-wand) authoring tool: `face_normal(verts, face)` (Newell's method — summed over every edge of the face, not just a first-three-vertex cross product, since the tile mesh's large concave side-wall/tab n-gons can have a near-collinear run of leading vertices along the top rim that a plain cross product misreads as flat-and-upward even though the face as a whole is a wall), `build_face_adjacency(faces)` (the same edge-keyed-by-`(min,max)` idiom as `manifold_check.assert_two_manifold`/`subdivision._edge_key`, but keeping incident face indices instead of just a count), `flood_fill_faces(verts, faces, seed_index, angle_threshold_deg, up_epsilon=0.05)` (BFS from the seed across shared edges; a candidate is included/expanded-through only if it faces upward past `up_epsilon` — a hard safety net independent of threshold size that keeps the fill off near-vertical walls and the downward bottom plate, since those are otherwise topologically reachable from the top surface — **and** its normal is within the threshold of the *seed's* normal specifically, not its immediate neighbour's, so the selection can't creep indefinitely across a gently curved dome), and `boundary_loop(faces, selected)` (walks the selected face set's boundary edges — those with exactly one incident selected face — into a single closed vertex-index loop, returning `None` on a pinch point or several disjoint loops, i.e. the selection wraps a hole or splits into islands; same edge-degree-checked walk as `tree_pads._boundary_loop`, generalized to arbitrary face arity rather than assuming triangles). `loop_to_xy(verts, loop)` reads tile-local (x, y) straight off the loop's vertex indices (mesh verts are already tile-local mm, same convention as `build_hex_tile`'s `verts_mm`). Flood fill is only ever an *authoring input method* here — `regions.HEXFINITY_OT_flood_fill_region` converts its result to a polygon and discards the face indices immediately, since (per `procedural_surfaces.region_mask`'s docstring) mesh face indices don't survive a subdivision/pad/path/notch rebuild the way a region's continuous-XY polygon does |
| `operators.py` | `rebuild_tile` marshals a tile's `surface_regions` (drawn Draw Area loops) through a local `_marshal_region(reg, name_fallback, seed)` helper (the dict-building body factored out so it's shared, not duplicated); the same helper is called once more, first, for `tile_props.surface_texture` (the whole-tile "Surface Texture" singleton — see `properties.py`) when its `surface_type != 'NONE'`, prepended to the `surface_regions` list with a distinct seed (`surface_seed ^ 0xA17EA000`, vs. each drawn region's `surface_seed ^ (idx * 2654435761)`) — reflecting its role as the base layer under Draw Area/Path Feature (the prepend is purely for readability: `mesh_builder._surface_offset_for_regions` sums every region order-independently, so nothing downstream needed to change). `rebuild_tile` also computes `path_features.path_specs(obj)` and passes it as `build_hex_tile`'s `path_features` kwarg, immediately after the `terrain_pads` computation — same shape as the `flora_pads`/`terrain_pads` plumbing just above it. `generate_map`, `clear_map` (destructive-only — deletes the whole map collection + all tiles/terrain/scatter/flora, incl. the Flora sub-collection, resets `is_generated`/`show_globals`; does **not** rebuild), `on_global_update` callback; `_REBUILDING` re-entrancy guard. `rebuild_tile(obj, finalize_flora=False)` computes `flora.pad_specs(obj)` and `terrain_pad_specs(obj)`, passing them as `build_hex_tile`'s `flora_pads`/`terrain_pads` kwargs *before* the build call, then (unchanged) calls `flora.purge_flora`/`flora.sync_flora` (mirroring the scatter block just above it) after the new mesh is assigned + depsgraph updated. `finalize_flora` (default `False`, unchanged at all pre-existing call sites) additionally computes `flora.notch_specs(obj)` and passes `flora_notches`/collects `flora_notch_warnings`/`flora_notch_ok_indices`/`flora_notch_heights` (`{index: pad_z}`, the exact pre-drill flat height per successful cut — passed to `flora.sync_flora` as `notch_heights` so it seats a tree/pin from the known height instead of raycasting into the hole it just cut); `flora.sync_flora(obj, ok_indices=notch_ok_indices, notch_heights=notch_heights)` is the *only* flora call now (a pin is created as a child of its own tree object inside that same function, not via a separate pass) — `purge_flora` unconditionally clears every tree (and therefore its pin child) each rebuild, so pins/notches only exist right after a finalize pass. `_rebuild_flora_tiles()` rebuilds every tile with a flora placement (without finalizing), for the `flatten_base`/`pad_blend_mm`/`penetration_mm` property update callbacks (a pad setting is scene-wide, not per-tile) — which also means those callbacks silently strip any existing pins/notches, mitigated by the panel's manual `hexfinity.finalize_flora` button (`flora.HEXFINITY_OT_finalize_flora`). `_build_map` seeds every new tile's P1–P6/center at `map_props.base_level` before the first build (corner callbacks short-circuit while `is_generated` is still `False`). `on_corner_changed` also fans a corner edit's **delta** across a multi-selection: `_MULTI_APPLYING` guards the fan-out, and `_ACTIVE_SNAPSHOT`/`seed_corner_snapshot*` (seeded from `panel.py`) recover the pre-edit value Blender's update hook hides. Also: `HEXFINITY_OT_import_terrain_object`/`HEXFINITY_OT_redrop_terrain_object` (STL terrain-object placement/parenting) and the terrain-object **plateau** subsystem — the sole mechanism that deforms a hex to match a terrain object (no separate raycast displacement layer exists): `EMBED_MM`/`SNAP_BASE_TOL_MM` constants, `_raycast_under_flat_base` (up-raycast "is this point under the model's flat base" test), `on_terrain_snap_changed(model)` (the `snap_mm`/`snap_damp_mm` update-callback entry point — just resolves `model.parent` and calls `rebuild_tile`, since `terrain_pad_specs` reads those properties fresh off the tile's children every rebuild), `terrain_pad_specs`/`_terrain_objects`/`_terrain_pad_grid_hits`/`_terrain_pads_signature`/`_pack_terrain_pads`/`_unpack_terrain_pads`/`_compute_terrain_pad_specs` (reuses the flora tree-pad mechanism — `terrain_pad_specs` samples a `TERRAIN_PAD_GRID_SPACING_MM` grid across each terrain child's bbox with `_raycast_under_flat_base`, tiles hits into pads via `terrain_pads.cluster_grid_hits`, and caches the (expensive) result on the tile as `hf_terrain_pads`/`hf_terrain_pads_sig` — a signature over every terrain child's transform + snap settings, since a plateau depends on ALL of a tile's terrain objects, not just the one whose slider moved). `_is_terrain_object(o)` is the per-object eligibility test — mesh, not a tile, not flora, not scatter — `_terrain_objects` filters a tile's children with the same rule; `_resolve_selected_hex(context)` resolves the active object (a tile directly, or a terrain object via `.parent`) to the target hex. `HEXFINITY_OT_generate_terrain_plateau` (`hexfinity.generate_terrain_plateau`) is the manual override: it deletes `hf_terrain_pads`/`hf_terrain_pads_sig` off the resolved tile — bypassing the cache the automatic path relies on, since a mesh edit at an unchanged transform doesn't change `_terrain_pads_signature` — then calls `rebuild_tile` and reports the resulting pad count; it always targets *every* terrain object on the resolved hex, not just a specifically-selected one. `HEXFINITY_OT_split_terrain_by_hex` (`hexfinity.split_terrain_by_hex`) is the destructive counterpart for a terrain object that spans several hexes (the plateau subsystem above only ever acts on the one tile a terrain object is parented to, so an overhanging model's neighbouring hexes never get a plateau): `_hex_split_candidates` cheaply pre-filters (bbox-vs-hex-bounding-square, no boolean math) which generated tiles a terrain object's world AABB could overlap, short-circuiting with "nothing to split" when only one tile is possible; `_cut_terrain_by_hex(context, terrain_obj, candidates, keep)` does the real work, boolean-`INTERSECT`ing (`EXACT` solver, same settings as `scatter.HEXFINITY_OT_merge_scatter`'s `UNION`) a duplicate of the terrain object against each candidate tile's world-positioned hex prism (`map.hex_prism_verts_faces`, extruded past the object's Z range by `SPLIT_PRISM_MARGIN_MM`) one tile at a time, discarding any empty result — this is also how material outside every hex is dropped, since it's simply never produced by any per-tile intersection rather than being tracked and deleted separately; `keep=False` tears every non-empty duplicate back down right after counting it (the `invoke()` dry run behind the operator's confirmation dialog, so the exact piece count is known and nothing leaks if the dialog is cancelled), `keep=True` finalizes each survivor in place (rename, copy `hexfinity_terrain.snap_mm`/`snap_damp_mm` from the original, parent to its tile with an explicit `matrix_parent_inverse`, mirroring `HEXFINITY_OT_import_terrain_object`'s parenting). `execute()` deletes the original object and force-rebuilds (cache-invalidate then `rebuild_tile`, same pattern as `HEXFINITY_OT_generate_terrain_plateau`) every tile that gained a piece plus the original's source tile, so plateaus reflect the new one-piece-per-hex ownership immediately. `HEXFINITY_OT_export_tiles` (per-tile STL export + dedup + manifest writing, via `tile_export.py`; `_terrain_children` excludes flora tree/pin objects from the fused tile export, `_terrain_objects` further excludes scatter boulders for the plateau subsystem; each finalized tree exports as **one merged** STL — `hex_qNN_rNN_treeII.stl` via `_export_flora_pair`/`tile_export.flora_placement_filename` — sharing the tile's own naming stem (not content-hash-deduped like tile files; every placement gets its own file), listed in a separate `flora_manifest.csv`/`.json` (single `file` column); since the pin is parented to the tree with a fixed local transform, `_export_flora_pair` rotates/moves only the tree object (the pin is carried along rigidly) 180° about the tree's own local X axis before export — flipping the whole rigid tree+pin body upside down so the canopy tip (previously the assembly's highest point) becomes the new lowest point at world z=0, and the pin (previously lowest, hanging into the socket) becomes the new highest point, pointing up — confirmed with the user as the intended print orientation; both objects are then selected and written with a single `wm.stl_export` call, the same object-count-agnostic triangle-soup merge `_export_objects` uses to fuse a tile with its terrain children (no boolean/topology fusion — two disjoint shells sharing one file); warns — doesn't block — if a tile has planted trees with no matching pin, i.e. flora was never finalized). `HEXFINITY_OT_copy_surface_texture`/`HEXFINITY_OT_apply_surface_texture` (`hexfinity.copy_surface_texture`/`hexfinity.apply_surface_texture`) back the Surface Texture box's "Copy Settings"/"Apply" buttons: a session-only module clipboard (`_SURFACE_TEXTURE_CLIPBOARD`, `None` until a copy — `apply`'s `poll()` gates on this to grey the button out — plus the `_SURFACE_TEXTURE_FIELDS` tuple of the 11 copyable field names, excluding `name`/`points`) captured from the active tile's `surface_texture` by Copy, then pasted by Apply onto the active tile plus every other selected tile via `_selected_other_tiles` (absolute overwrite, not the corner-delta fan-out's delta). ## Invariants — preserve when editing

- **bpy-free rule**: `mesh_builder.py`, `map.py`, `manifold_check.py`, `procedural_surfaces.py` (incl. all scatter geometry math), `subdivision.py`, `tile_export.py`, `tree_pads.py`, and `terrain_pads.py` must never import `bpy`. That isolation is what lets the pytest suite run against Blender's bundled Python without launching Blender. `regions.py`/`scatter.py`/`flora.py`/`path_features.py` themselves do import `bpy` — keep object/raycast/boolean/STL-import/image-loading code there, and keep any pure-math helpers extracted into it bpy-free (e.g. `path_features.py`'s snap-point geometry lives in `map.py`, and its curvilinear/texture-sampling math lives in `tree_pads.py`, instead).
- **Manifold guarantee**: every built tile is validated by `assert_two_manifold()`; failure raises loudly so silent mesh corruption is caught.
- **Tab geometry is hardcoded** in `mesh_builder.py` (`TAB_WIDTH_MM`, `TAB_HEIGHT_MM`, `TAB_DEPTH_MM`, `TAB_HOLE_TOLERANCE_MM`) — these constrain minimum base thickness and diameter. Check the constants before changing related values.
- **Corner sync**: `SHARED_CORNERS` in `map.py` defines which neighbours share each corner; `on_global_update` propagates per-corner writes across seams.
- **Scatter kind contract**: a `scatter` `Surface` has `generator=None`, so `surface_offset()` returns `0.0` (zero displacement) and the `GENERATING` test fan-out (`s.generator is not None`) excludes it — do not give a scatter surface a generator. Scatter objects are regenerated by `scatter.purge_scatter` + `sync_scatter` on every `rebuild_tile`; the seating raycast must run *after* the tile mesh is assigned and the depsgraph updated so it samples current (not stale) geometry.
- **Brush displacement layer**: top-surface verts are registered first in `build_hex_tile` (indices `0 .. num_top-1`), and `num_top` depends only on `smoothness_passes + resample_density` (see `top_vertex_count`, pinned to the builder by `test_top_vertex_count_matches_builder`). `obj["hf_brush_disp"]` is a `float[num_top]` z-offset layer applied (clamped to `base_thickness_mm`) inside the builder and re-sampled on every rebuild; `rebuild_tile` drops it when the length no longer matches `num_top` (a subdivision/resample change), which is the intended "paint survives height edits only" contract.
- **Tree-pad vertex ordering**: `tree_pads.refine_and_flatten` only ever *appends* new vertices — never inserts — so every index below the caller's original vertex count stays valid. `mesh_builder.build_hex_tile` calls it once (on `flora_pads` + `terrain_pads` concatenated) strictly between top-vertex displacement and the "Bottom of the tile…" section, so pad-refinement verts land at indices `>= num_top` and strictly before any bottom/side/tab vertex `add_vert` registers — planting/unplanting a tree, or a terrain object's plateau appearing/disappearing, therefore never disturbs `top_vertex_count()` or `hf_brush_disp`. Refinement must also never split a rim edge (`protected_edges`, collected from the same `rim_chains` the side wall's `top_rim_key` depends on) or the wall n-gon desyncs. `tree_pads.cut_notches` (run after the merged pad pass, only when finalizing flora) keeps the same append-only contract for its wall/floor verts, but *does* mutate existing vertices in place: a socket's boundary-loop vertices get their (x, y) snapped onto an exact circle (z untouched), and any genuinely-interior vertex of the drilled region sinks straight to the socket floor (z changed, same index, reused for the floor mesh so nothing is ever orphaned) — both safe since the brush layer only ever reads/writes Z by index and it already ran earlier in the pipeline.
- **Layer order / Path Feature displacement**: the user-facing mental model is a stack — Water, Land Surface, Draw Area (regions), Path Feature — and the pipeline already reflects it in two stages, not one uniform mechanism. Regions (`_surface_offset_for_regions`) **sum** every region's masked contribution across the *whole tile* in a single order-independent pass (a future Water/Land Surface slots in here, as new `procedural_surfaces.SURFACES` entries authored via the existing whole-tile-region mechanism — no new plumbing). `combined_pads` (flora+terrain) then locally flattens on top of that. `path_features` (`tree_pads.refine_and_displace_along_path`) runs *last*, carving/raising on top of whatever the pad pass left — matching Path Feature's position as the topmost layer. Same append-only vertex contract as the pad pass (new verts land after the existing range, never inserted). Heightmap convention for any future texture-driven displacement (Path Feature now, Water/ground-texture later): **white = raised, mid-gray = unchanged, black = carved** — `offset = (gray - 0.5) * 2 * depth_mm`.
- **Bake**: `hexfinity.bake_tile`/`hexfinity.unbake_tile` (see `operators.py`'s row for the mechanics) freeze flora/terrain pads, flora notches, path-feature carving, and the terrain brush into id-properties replayed instead of recomputed — displacement regions (Draw Area/Surface Texture) are deliberately excluded and always stay live, applying on top of a baked or unbaked top surface identically, since they only ever touch the `0 .. num_top-1` prefix, same as the brush. A baked tile's pad/terrain/notch/path portion is a snapshot: it's only valid until something it was fit against changes (`_bake_signature` covers both the top-surface shape *and* every flora placement/terrain-object transform/path-feature point), at which point `rebuild_tile` silently reverts just that portion to live and prints a console notice — never silently misapplies stale geometry. The frozen brush contribution (`hf_baked_top_offset`) is a different, simpler case: it's a `num_top`-indexed z-delta with the exact same "survives height edits, dies on a vertex-count change" contract the live `hf_brush_disp` layer already has, so it's invalidated independently of (and less often than) the pad/terrain/notch/path portion.
